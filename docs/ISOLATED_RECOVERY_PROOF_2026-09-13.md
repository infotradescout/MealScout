# Isolated recovery proof runner

`scripts/verifyRecoveryIsolated.mjs` runs only in an explicitly selected non-root Linux x64 proof build. It requires a clean checkout at `RENDER_GIT_COMMIT`, rejects ambient database/payment/mail credentials and loadable environment files, and passes a narrow tooling environment to child processes. The two tracked `.env.*.example` templates are inert; no application server is started.

The runner installs the canonical npm lockfile, checks types, builds the application and executes the existing calendar, critical smoke, ordering, integrated marketplace, webhook and menu/LISA tests. It installs pinned PostgreSQL 16 tooling outside the checkout. The existing migration142 proof owns its first native cluster. The new transport adapter then owns a separate fresh cluster, pushes the canonical schema, applies the same migrations090/142 as the existing Docker orchestrator, and runs that existing stateful fixture unchanged. Payments and notifications in this fixture use intercepted providers and synthetic data. Both fixtures stop their own clusters before returning.

The existing nine credential-free Playwright files run on all five configured desktop/mobile projects against a loopback static server serving the production build. `FRONTEND_URL` prevents Playwright from starting an application server. Missing API mocks receive HTTP404; there is no backend or external database. Browser failures, flaky results, skips, zero executed tests or a changed checkout fail the proof. The runner publishes only its summary, exact SHA/tree, executed step outcomes and browser counts. A failed command exits nonzero and prints the failure summary to build logs; a failed deployment must never be described as successful proof.

Deployment configuration is a separate static-only Render service with automatic deploys disabled, no paid plan, database, environment group, production domain or provider credentials. Its build makes a fresh temporary checkout of the selected commit and copies only `test-results/recovery-isolated-report` into the static publish directory after a successful run. This runner does not call production startup, migration deployment, live-provider smoke commands or authenticated customer workflows.

Local preparation: both JavaScript files pass `node --check`; the explicit-mode guard was executed and failed before any tests. Native PostgreSQL/browser acceptance remains unexecuted locally because this workspace runs as root and cannot launch the required native runtimes. Hosted acceptance must be reported from its actual run and commit, independently of historical evidence. Passing this scope does not establish live Stripe behavior or complete production readiness.
